# Changelog

What changes for script users in each release of EasyUO Reforged. New entries go under **Unreleased**; `tools/release.ps1` turns that section into the next version's, and the release page on GitHub shows it. Keep each entry on one line, because the release page shows every line break. Everything Reforged adds to EasyUO 1.5 is listed by topic on [What's new in Reforged](https://ilpersi.github.io/EasyUOReforged/reforged/whats-new/).

## Unreleased

### Added

- **`list`: real lists of values in scripts.** `list add loot POF KUF` adds values; `list get`, `set`, `insert`, `delete` and `count` work on positions from 1; `list indexof` and `list find` search, ignoring case; `list sort` orders by number or as text, `down` for largest first; `list split` cuts a text (a `#Property`, a comma-separated line) into a list and `list join` puts it back; `list merge`, `list intersect` and `list subtract` build a new list from others, each value once (`keepduplicates` keeps repeats in a merge). The answers are in the new `#ListRes`. Lists survive the restart at the end of a script. The Watches panel shows each list, and *Edit Values…* (or a double-click) edits its values, one per line, while the script runs or is paused; *Tools → VarDump* lists them, and `EUOCli`'s end report and `euo_vars` give them as `lists`. A line starting with the word `list` used to be ignored and is now this command; a sub or label called `list` keeps working. See [`list`](https://ilpersi.github.io/EasyUOReforged/commands/list/).
- **`client_beta.exe` 7.0.119.0 is supported.** On this beta `#CharID`, `#CharName`, `#BackpackID`, the status values (`#Hits`, `#Str`, `#Gold`, …), `#CharStatus` and `#FindRep` read nothing or nonsense, `#CliLang`, `#TP`, `#CliTop`, `#NextCPosX`, the last target, the last spell and skill, the hands, `#LLiftedID`/`#LLiftedType`/`#LLiftedKind` and `#CursKind` read the wrong place, and `event macro`, `event ContTop`, `event Drag`, `event PathFind`, `path can` and `scanbuffs` did nothing. They now read and act where this build keeps them. See [Known limitations](https://ilpersi.github.io/EasyUOReforged/reforged/known-limitations/).

### Changed

### Fixed

- **`#GumpReply` records your clicks with no script asking first.** Clicks on a server gump were recorded only after a script had read `#GumpReplyCnt` or run `exevent GumpReply` since the client started, so after opening a gump and clicking, `#GumpReply` still read `N/A`. The editor now starts the recording as soon as it finds the client (while no script is running), so you can click and then read `#GumpReply` in the variable list or a script. Under `EUOCli`, reading `#GumpReply` in a script now starts it too, and so does `GetGumpReply` in `uo.dll`, which also returns nil, not zeros, while nothing was recorded yet. A click made before the recording started is still lost. See [`#GumpReply`](https://ilpersi.github.io/EasyUOReforged/variables/gumpreply/).

## v26.11.23 - 2026-11-23

### Added

- **`timer`: named timers for deadlines, "every 30 seconds" and stopwatches.** `timer start save 30s` starts a timer; `timer due save`, `timer left save` and `timer elapsed save` say in the new `#TimerRes` whether it is due (`#true`/`#false`), how many milliseconds are left, or how long it has run. A timer that was never started counts as due, so a loop's first round runs at once. Unlike deadlines built on `#SCnt`, nothing but `timer start` moves a timer, and timers survive the restart at the end of a script. A line starting with the word `timer` used to be ignored and is now this command; a sub or label called `timer` keeps working. See [`timer`](https://ilpersi.github.io/EasyUOReforged/commands/timer/).
- **`str decimal`, `duration`, `date`, `clock` and `datetime`: times, dates and decimals ready to show.** `str decimal 953 1` gives `95.3` (skill tenths), `str duration 3725` gives `1:02:05`, `str date #Date` gives `2026-11-22` and `str clock #Time` gives `14:30:05`. All but `decimal` take an optional format with the usual `dd`, `mmmm`, `yyyy`, `hh`, `nn`, `am/pm` letters and plain text with no quotes, such as `str date #Date dddd d mmmm yyyy` (`Sunday 22 November 2026`) or `str duration %secs [n] min`; names, separators and the decimal point are the same on every computer, whatever the Windows settings. See [Time and numbers](https://ilpersi.github.io/EasyUOReforged/commands/str/#time-and-numbers-reforged).
- **An outline of the script, left of the editor.** A new panel lists the script's subs, its labels (under the sub they are in) and the lines that build `menu` windows: click one to jump there, and *Edit → Go Back* (Alt+Left) returns. It selects the sub the cursor is in, its filter box finds an entry by name, **A-Z** sorts the list, and a sub that no `gosub` names is grey. *Control → Show Outline* hides it; its width is kept. See [The outline](https://ilpersi.github.io/EasyUOReforged/guide/debugging/#the-outline).
- **`logfile`: write log files and text files from a script.** `logfile open run mining.log` opens a file, and `logfile info Started`, `logfile warning Low on picks` write timestamped lines with their level, script and line number to it and to the Output panel; `logfile level` and `logfile set` choose which levels each one keeps, the line format, and a new file by size or every day (`logfile set run daily`). `logfile write cfg set % , hp %hp` writes a line exactly as given, so settings saved this way load back with `call`, with no two-second wait, no console window and no trouble with `>`, `|`, `&` or `%` in the text, as `execute cmd /c echo ... >> file` had. The new `#LogRes` says `OK` or why a file can't be written. Under `EUOCli run` files stay in the program folder unless `--allow logfile`. A line starting with the word `logfile` used to be ignored and is now this command; `log` is unchanged. See [`logfile`](https://ilpersi.github.io/EasyUOReforged/commands/logfile/).

- **`send get`, `post`, `put`, `delete` and `download`: talk to web servers over HTTP and HTTPS without running the answer.** `send get https://example.com/version.txt` puts the page in the new `#SendReply`, its HTTP status in `#SendCode` (`200`, `404`, …, or `0` when no answer came) and `OK` or the reason in `#SendRes`; `send post {url} {data}` sends form data, or JSON with a `Content-Type` line in `#SendHeader`, so a script can post to a Discord webhook or a web service; `send download {url} {file}` saves a file, which a script can then `call`. Stop and Pause work while a request waits. The original `send httppost`, which runs the reply as a script, works exactly as before. See [`send`](https://ilpersi.github.io/EasyUOReforged/commands/send/).
- **Watches, and the values a step changed.** A new Watches panel at the bottom of the window, shown by default (*Control → Show Watches* hides it), lists the variables you chose and every variable the script uses, found by itself, including the ones a run makes such as `%list3`. **Ctrl+F5** adds the variable under the cursor; each script file keeps its own watches. Each time the script pauses (a step or a breakpoint), the variables whose value changed since the previous pause turn red, name and value, and hovering one shows what it was. See [Watches](https://ilpersi.github.io/EasyUOReforged/guide/debugging/#watches).
- **A Discord button.** The toolbar's new *Discord* button, right of *Website*, and *Help → Discord* open the project's official Discord channel. See [The window](https://ilpersi.github.io/EasyUOReforged/guide/first-script/#the-window).
- **Search folders for `call`: keep shared scripts in a library folder.** `call helper` used to look only in the folder of `EasyUOReforged.exe`; now, when the file isn't there, it also looks in the folders of the new *Tools → Search Folders* list (managed like the Windows `PATH` list: New, Browse, Delete, Move Up and Down), then in the folders of an `EUOPATH` environment variable, and under `EUOCli` in the folders given with `--euopath` or the tools' `euopath` argument. In each folder it tries the name, then `.txt`, then `.euo`. The program folder is still searched first, so existing scripts load the same files. See [Where call looks for the file](https://ilpersi.github.io/EasyUOReforged/commands/call/#where-call-looks-for-the-file).
- **`str urlencode` and `str jsonescape`.** They make a value with spaces, `&`, `=` or quotes safe inside form data or a JSON body for `send`. See [Encode for send](https://ilpersi.github.io/EasyUOReforged/commands/str/#encode-for-send-reforged).

### Changed

- **`sql open` finds a database in the search folders.** A name that isn't in the folder of `EasyUOReforged.exe` is now also looked for in the *Tools → Search Folders* list, `EUOPATH` and, under `EUOCli`, the `--euopath` folders, and `sql open mychar` also finds `mychar.db` or `mychar.sqlite`. A database found nowhere is still made in the program folder, as before. See [Where sql open looks for the file](https://ilpersi.github.io/EasyUOReforged/commands/sql/open/#where-sql-open-looks-for-the-file).
- **The call stack and the Output panel run the whole width of the window.** They used to sit under the script only, between the outline and the variable inspector; now they share the bottom of the window with the new Watches panel, each shown one taking an equal part of the width, and the outline, the script and the variable inspector end above them.

### Fixed

- **Ctrl+V and the other Edit keys work in the variable filter box.** While you typed in the filter box above the variable inspector, Ctrl+V, Ctrl+C, Ctrl+X, Ctrl+A and Ctrl+Z pasted, copied, cut, selected or undid in the script instead of the box. They now act on the box, and so do the same commands from the *Edit* menu.

## v26.11.16 - 2026-11-16

### Added

- **`scangumps`: see every gump window that is open, not only the one on top.** `scangumps` lists the open windows front to back, and `#GumpIndex` walks them like `#FindIndex` walks `finditem`'s results. For each one, the new `#Gump…` variables give its name, position, size, graphic (`#GumpArt`: the backpack is `YE`), whether it is minimized and the container or character it belongs to. A gump the server sent also has `#GumpTypeID`, which is the same every time the server opens that gump, so a script can tell which one is open. `scangumps T_JHEIIPI` or `A_YE` keeps only matching windows. It only reads the client. A line starting with the word `scangumps` used to be ignored and is now this command. See [`scangumps`](https://ilpersi.github.io/EasyUOReforged/commands/scangumps/).
- **`exevent GumpReply`: answer a gump the server sent without clicking.** `exevent GumpReply JHEIIPI 1` presses button 1 of the open gump with that type ID, and `exevent GumpReply %menu 2 3/7 5:Iron_Golem` also ticks checkboxes 3 and 7 and fills text field 5. The server gets the same answer as for a click, with the serial the gump has now, and the window closes. `#GumpReplyRes` says `sent`, `nogump` (not open: nothing sent) or `error`, and `#GumpReply` keeps the answer, so `exevent GumpReply #GumpReply` sends it again the next time that gump opens. It also records the answers you click yourself, and `#GumpReplyCnt` goes up with each: to learn what a gump expects, click once and read `#GumpReply`. Old EasyUO ignored this sub-command and still does. See [`exevent GumpReply`](https://ilpersi.github.io/EasyUOReforged/commands/exevent/gumpreply/).
- **`moveitem`: move an item into a container and know whether it arrived.** `moveitem #FindID %bag` picks the item up, drops it into the bag, waits for each step, tries again when that is safe, and sets the new `#MoveRes` to `ok`, or says why not (`refused`, `nolift`, `left`, `noitem`, `nodest`, `held`, `error`). Without an amount it moves the whole stack; `moveitem %id %bag 10 40 40` moves 10 to a place in the bag. It checks the client's item list, never the journal, so it works whatever the client's language. It replaces the drag, wait, drop and retry subs scripts write by hand. A line starting with the word `moveitem` used to be ignored and is now this command. See [`moveitem`](https://ilpersi.github.io/EasyUOReforged/commands/moveitem/).
- **`log`: follow a script while it runs.** `log The sum is %sum` writes a line to the editor's new Output panel, with the time, and the script goes on. Unlike `display` it never waits for a click, so it can go in a loop, and unlike `event sysmessage` it needs no client and the lines stay. The panel opens by itself at the first line; *Control → Show Output* and *Clear Output* show, hide and empty it. A line starting with the word `log` used to be ignored and is now this command. See [`log`](https://ilpersi.github.io/EasyUOReforged/commands/log/).
- **`EUOCli run`: run a script from the command line.** It runs a script with nobody watching and prints what it logs, what its `display` boxes would have shown, and why and where it ended. It is made for scripts nobody has read yet: it uses no UO client unless you add `--client 1`, it always ends (after a timeout, or when a script without `halt` starts over), and `execute`, `shutdown`, `terminate`, `uoxl` and `send` stop the run unless you allow them. `EUOCli vars #CharPosX #ContName` reads variables from a client without a script, and `EUOCli clients` lists the clients. See [Run a script](https://ilpersi.github.io/EasyUOReforged/guide/euocli/#run-a-script).
- **`EUOCli mcp`: tools for AI agents, and a script they can step through.** Agent programs that take tools (the Model Context Protocol) start `EUOCli mcp` and get `euo_check`, `euo_run`, `euo_vars`, `euo_docs` and the rest without a shell. A run now stays alive between calls, so the agent can follow it, pause it, set breakpoints, step line by line and read its variables, as you do in the editor. The tool `euo_run` can't reach a UO client or run a blocked command, whatever is passed to it, so it is safe to allow for good; `euo_run_live` is the only tool that acts on your character, and asks for its own approval. The script stops when the agent closes. See [Tools for an agent](https://ilpersi.github.io/EasyUOReforged/guide/euocli/#tools-for-an-agent-euocli-mcp).
- **`EUOCli init`: set a script folder up for an AI agent in one step.** `EUOCli init C:\Games\UO\Scripts` copies the agent pack there as a Claude Code skill, writes `AGENTS.md` for other agents and adds the `.mcp.json` entry for the tools. An `AGENTS.md` or `.mcp.json` that is already there keeps what it holds. Run it again after an update to replace the pack. See [Set a folder up for an agent](https://ilpersi.github.io/EasyUOReforged/guide/euocli/#set-a-folder-up-for-an-agent).
- **`EUOCli docs`: the documentation in the terminal.** `EUOCli docs finditem` prints the page of a command or `#variable` from the files that came with the program, and `EUOCli docs --search journal` lists what mentions a word. See [Look up the documentation](https://ilpersi.github.io/EasyUOReforged/guide/euocli/#look-up-the-documentation).
- **`EUOCli check`: find the mistakes EasyUO never reports.** EasyUO skips a line it can't understand without any error, so a typo shows up only as a script that does nothing. The new `EUOCli.exe` in the release zip reads a script without running it and lists them with line and column: a word that is not a command, a `#variable` that doesn't exist, a wrong sub-command, a missing space in a condition, braces or `repeat` / `until` that don't pair up, a `gosub` or `goto` to nowhere, and a script that restarts because it has no `halt`. It needs no client, and `--json` gives the findings to a program. See [Check a script with EUOCli](https://ilpersi.github.io/EasyUOReforged/guide/euocli/).
- **An agent pack, so AI coding agents can write EasyUO scripts for you.** The new `agent` folder of the release zip holds the language rules, every command and `#variable` on one line, and a reference page for each, as plain files that Claude Code, Codex, Cursor and other agents read, so they look names up instead of inventing commands that EasyUO would skip without an error. For Claude Code it is a ready-made skill; other agents read its `AGENTS.md`; a chat can read <https://ilpersi.github.io/EasyUOReforged/llms.txt>. The agent writes and changes scripts, checks them with `EUOCli check` and tries their logic with `EUOCli run`, without a client; it runs a script on your character only after you say yes. See [Write scripts with an AI agent](https://ilpersi.github.io/EasyUOReforged/guide/agents/).
- **`menu Memo` can wrap its lines.** With the 1.6 `menu`, `menu SetProp notes wordwrap #true` breaks a memo's long lines at its right edge instead of letting them run past it, and `menu SetProp notes scrollbars 2` keeps only the vertical scroll bar (0 none, 1 horizontal, 2 vertical, 3 both). A new memo looks as before, and `menu Get` still returns the text as written, with no `$` where a line was only wrapped. The MENU Designer has both as rows of a memo. See [menu Memo](https://ilpersi.github.io/EasyUOReforged/commands/menu/memo/#wrapping-and-scroll-bars).
- **Three new documentation pages for writing scripts that work.** [Common mistakes](https://ilpersi.github.io/EasyUOReforged/language/common-mistakes/) lists the rules scripts break most often, such as spaces around every word, `-1` for true and `halt` at the end, each with an example whose result is checked against the interpreter. [Common patterns](https://ilpersi.github.io/EasyUOReforged/guides/patterns/) shows how to find and use an item, target, move items, wait for a gump or a journal line, walk and loop. [Finding IDs and types](https://ilpersi.github.io/EasyUOReforged/guides/finding-ids/) shows how to read the values a script needs from your own game.

### Changed

- **A new icon.** EasyUO Reforged, the MENU Designer, `EUOCli` and the documentation site now share one icon: the EasyUO emblem, its ring turned into a gear with a run button in the middle, engraved in black and cream on a green tile. The small sizes of the taskbar and title bar are drawn pixel by pixel so they stay sharp.

### Fixed

- **`client_beta.exe` 7.0.118.132 reads the last target, the lifted item, the hands and the game area height right.** On this beta `#LTargetID`, `#LTargetKind`, `#LSkill`, `#LSpell`, `#RHandID`, `#LHandID`, `#LLiftedKind`, `#LLiftedType`, `#NextCPosX`, `#CliLang` and `#CliYRes` read the wrong place, so `event Drag`, Last Target, `moveitem` (which answered `held`) and `nextcpos` did not work, and setting `#CliYRes` crashed the client. `event macro` also stopped doing anything once the client had played one of its own macros, such as Alt+J for the journal. They now read where this build keeps them, and `event macro` works whatever the client played before. See [Known limitations](https://ilpersi.github.io/EasyUOReforged/reforged/known-limitations/).
- **Stop now stops at once during a wait.** When you pressed Stop while a script was inside a `wait`, `target`, `waitfor` or another waiting command, the line after it could still run once, about one time in four. The original EasyUO did the same. Stop now ends the wait and runs nothing more.
- **`exevent Equip` sends the right request.** In EasyUO Reforged the command built its request with the length and every item ID written backwards, so the server could not read it and nothing was equipped. It now sends the same request as the original EasyUO and as `uo.dll`'s `Equip`, which was not affected. See [exevent Equip](https://ilpersi.github.io/EasyUOReforged/commands/exevent/equip/).
- **`#CliLang` reads the client language on `client.exe` 7.0.117.1 and 7.0.117.33.** On these clients it was always empty, because EasyUO Reforged looked for the language where the client keeps something else. It now reads `ENU`, or your client's own language code, as on older clients and on `client_beta.exe`. `uo.dll`'s `CliLang` is fixed the same way. See [#CliLang](https://ilpersi.github.io/EasyUOReforged/variables/clilang/).
- **`#EnemyHits` reads the enemy's health in percent on every shard.** EasyUO multiplied the client's number by 4, which is right only on shards that send health out of 25 (RunUO), so on ModernUO shards it read 4 times too high, up to 400. It now divides by the maximum the shard sent: on shards that count out of 25 the numbers are the same as before. On `client_beta.exe` 7.0.117.31 it read `N/A` in combat, or the maximum after you selected a mobile with the targeting macros: it now follows the enemy you attack. `uo.dll`'s `EnemyHits` is fixed the same way. See [#EnemyHits](https://ilpersi.github.io/EasyUOReforged/variables/enemyhits/).
- **`event Drag` picks items up again on `client_beta.exe` 7.0.117.31, and `#LLiftedKind` and `#LLiftedType` follow the item on the cursor.** On this client `#LLiftedKind` read 65536 with nothing on the cursor, so `event Drag` believed you already held something and did nothing, and `#LLiftedType` never changed. Both now read the client's own values: `#LLiftedKind` is 1 while an item hangs on the cursor and 0 otherwise. `uo.dll`'s `LLiftedKind`, `LLiftedType` and `CliDrag` are fixed the same way. See [event Drag](https://ilpersi.github.io/EasyUOReforged/commands/event/drag/).
- **`#FindRep` reads the notoriety on `client_beta.exe` 7.0.117.31.** It read 255 for every character found. It now reads 1 to 7 as on the other clients. See [#FindRep](https://ilpersi.github.io/EasyUOReforged/variables/findrep/).
- **`#ContHP` reads health bars on `client_beta.exe`.** It read 0 on your own health bar and meaningless numbers such as 43338 on a pet's. It now reads the health in percent, as on the other clients. `uo.dll`'s `GetCont` is fixed the same way. See [#ContHP](https://ilpersi.github.io/EasyUOReforged/variables/conthp/).

## v26.11.09 - 2026-11-09

### Added

- **`str replace`, `part`, `trim`, `join` and `concat`: work on text without hand-written loops.** `str replace %s _ #SPC` replaces every `_`, or removes it if you leave out what to replace it with. `str part 1_50_00 _ 2` takes the second field (`50`), and a `for` with `str count` goes through all of them. `str trim %s` removes spaces and `_` from both ends, or the characters you name. `str join _ %a %b %c` and `str concat %a %b` put texts together. See [`str`](https://ilpersi.github.io/EasyUOReforged/commands/str/), including how spaces differ between `#Journal` and `#Property`.
- **`findjournal`: search the journal in one line.** For example `findjournal %j * 3s fizzles you_must_wait` looks through every line since you saved `#JIndex` in `%j`, in any colour, for either text, and waits up to 3 seconds. Give a colour instead of `*` to match only lines of that colour, or `*` as the text to match any line. [`#JFound`](https://ilpersi.github.io/EasyUOReforged/variables/jfound/) gives the line's number, and `#Journal` and `#JColor` hold the line, so nothing is missed when lines arrive together and `deletejournal` isn't needed. See [`findjournal`](https://ilpersi.github.io/EasyUOReforged/commands/findjournal/).
- **`waitfor`: wait until a condition is true, or give up after a timeout.** For example `waitfor #ContName = generic_gump 5s`. The condition works like `if`, including `&&`, `||` and nested parentheses, so one line can replace a hand-written polling loop. [`#WaitRes`](https://ilpersi.github.io/EasyUOReforged/variables/waitres/) then says which happened: `#true` if the condition was met, `#false` on timeout. Pressing Pause doesn't use up the timeout, and Stop ends the wait at once. See [`waitfor`](https://ilpersi.github.io/EasyUOReforged/commands/waitfor/).
- **A filter box above the variable inspector**: type part of a name, such as `hits`, and only the matching variables stay in the tree. It takes regular expressions too, like the Find window: `^max` keeps the names that start with `Max`. Esc clears it. See [Your first script](https://ilpersi.github.io/EasyUOReforged/guide/first-script/#the-window).
- **Ctrl+click a sub or label name to jump to it**: hold Ctrl over the name after `gosub` or `goto`, it underlines, and a click takes you to its `sub` line or its `label:` line. **Alt+Left** (*Edit → Go Back*) returns to where you clicked. The jump goes where the script would: to the last `sub` of that name, and to the nearest label, the one below first. A name held in a variable is not a link. See [Editor features](https://ilpersi.github.io/EasyUOReforged/guide/debugging/#editor-features).

### Changed

- **New toolbar and menu icons**, in the same outline style as the MENU Designer, and every toolbar button now shows its name under the icon. Start is green, Pause orange, and Stop and Stop All red, so the script controls stand out; a toolbar button that is switched off turns one even grey. The buttons, their order and their tooltips are unchanged. New Client and Swap To Next Client are now window icons instead of the *CLI NEW* and *CLI SWAP* lettering. See [Your first script](https://ilpersi.github.io/EasyUOReforged/guide/first-script/#the-window).
- **A new application icon**, for the taskbar, the title bar and the executables of EasyUO Reforged and the MENU Designer: the original emblem, glowing on an anvil. It now comes in sizes from 16 to 256 pixels, so it stays sharp instead of being rescaled from one small image.
- **One Find/Replace toolbar button instead of two**: the Find and Replace buttons opened the same window, so they are now a single button. *Edit → Find…* (Ctrl+F) and *Edit → Replace…* (Ctrl+H) are unchanged. See [Find and replace](https://ilpersi.github.io/EasyUOReforged/guide/debugging/#find-and-replace).
- **The [`display`](https://ilpersi.github.io/EasyUOReforged/commands/display/) message box is titled *Reforged Message*** instead of *EUO Message*. Its buttons, text and `#DispRes` are unchanged.
- **The Website button** (and *Help → Website*) now opens the [EasyUO Reforged project page](https://github.com/ilpersi/EasyUOReforged) instead of easyuo.com.
- **The variable inspector is regrouped.** Its groups are now the same as the [variable reference](https://ilpersi.github.io/EasyUOReforged/variables/) on the site, and the groups and the variables inside them are in alphabetical order. *Extended Info* and *Miscellaneous* are split into *Cursor & targeting*, *Journal & messages*, *Script*, *Skills* and *Time*. *Status bar* keeps the variables read from the status bar. `#ContSize` and `#CurPath` are now shown too.
- The inspector remembers which groups you left open by their names, so adding a group no longer opens the wrong ones. The groups you had open before this version start closed once.
- `uo.dll`'s [`GetItem`](https://ilpersi.github.io/EasyUOReforged/dll/getitem/) returns the item's equip layer as an 11th value, after its usual ten: the same number as `#FindLayer`, or 0 when nobody wears the item. The separate `GetItemLayer` call that v26.11.02 added is gone; read the layer from `GetItem` instead.

### Fixed

- **The editor colors commands, `#variables` and operators however you write them**: `halt` is now bold like `HALT`, and `#charPosX` is colored like `#CHARPOSX`, as the language itself ignores case.
- **A menu button shows its new caption right away**: after [`menu Set`](https://ilpersi.github.io/EasyUOReforged/commands/menu/set/), or [`menu SetProp`](https://ilpersi.github.io/EasyUOReforged/commands/menu/setprop/) `text` in a 1.6 menu, the button kept showing its old caption until you clicked it or something covered the window.
- **The Reopen toolbar button lists your recent scripts again**: clicking it did nothing; it now drops down the last opened scripts, as in EasyUO 1.5, and picking one opens it.

## v26.11.02 - 2026-11-02

### Added

- **The MENU Designer** (`EUOMenuDesigner.exe`, in the zip): lay out EasyUO 1.6 `menu` windows by drawing them, preview them, and turn them into script lines, or read an existing script's window back in. See [The MENU Designer](https://ilpersi.github.io/EasyUOReforged/designer/).

- **`#FindLayer`**: the layer a character wears the object `FindItem` selected in. `uo.dll` gets `GetItemLayer`.

### Changed

- `path` walking on a mount sends steps fast enough for a full-speed run. The [Running](https://ilpersi.github.io/EasyUOReforged/commands/path/#running) section explains when the client walks and when it runs.
- `FindItem` also fills `#FindLayer`; nothing else it does has changed.
- [`#BuffBarOpen`](https://ilpersi.github.io/EasyUOReforged/variables/buffbaropen/) is `#true` (`-1`) when the buff bar is open, where it used to be `1`, so it can be compared with `#true` and `#false`. A script that compares it with `1` must compare it with `#true` now.
- `uo.dll`'s [`GetBuff`](https://ilpersi.github.io/EasyUOReforged/dll/getbuff/) returns the seconds a buff has left at the moment it is called, like `#BuffTime`, instead of the seconds it had when `ScanBuffs` ran.
- The [`#CharStatus`](https://ilpersi.github.io/EasyUOReforged/variables/charstatus/) page now explains every letter, and how to tell poison from a yellow health bar.
