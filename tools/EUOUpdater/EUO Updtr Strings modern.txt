// EUO Updtr scan strings for the RELOCATABLE ("modern", DYNAMIC_BASE) client builds -- the
// 7.0.117.1 beta (client_beta.exe, PE time/date stamp 6AC94360) is the first.
//
// "EUO Updtr Strings 6062 and newer.txt" does not match these builds at all: they are built
// with a newer compiler, loaded away from $400000 and have ~10% more code. EUO Updtr scans the
// whole code section of such a client and prints LINK-TIME addresses (as if loaded at $400000),
// which is the form uoclidata.pas stores -- paste them into a new ModernBuilds Addrs list.
//
// Every line was generated mechanically (address-like operands, rel32 branch targets and
// ebp/esp displacements are wildcards, joker byte chosen so it never collides with a fixed
// byte) and then checked two ways: exactly ONE match in the whole code section of the beta, and
// resolving to the address that was derived by hand and verified in the running client -- both
// statically against the file and live against the process. A second line for the same name is a
// fallback anchored in a different function (EUO Updtr shows only the first that matches).
//
// Format: pattern ; joker byte ; offset ; X = address itself / C = read the dword there /
//         CB = follow the rel32 there ; adjust ; {name}
//
// These patterns assume the same code generation. Another beta of the same compiler normally
// moves the addresses (wildcarded here) and leaves the code alone; a different compiler version
// needs them re-derived -- see docs/adding-client-support.md.
// B_*/F_* layout constants are not scannable (B_SKILLDIST excepted, see {SKILLNORM}); see
// SysVarModernLayout in uoclidata.pas.
